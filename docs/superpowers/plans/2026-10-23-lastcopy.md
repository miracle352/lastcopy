# LastCopy file-by-file implementation plan

Approved brief: ../../PRODUCT_SPEC.md and ../../../LASTCOPY_CODEX_PROMPTS.md.
Execution provenance: Codex desktop, Windows, 2026-10-23. No framework installed
just to execute this plan. Only Stage 1 was requested. Do not start Stage 2
automatically. Product constraints are gates, not aspirational copy.

## Architecture decisions

New standalone private repository: the parent workspace is a collection of
unrelated experiments, not an existing LastCopy stack. Leave it unchanged.
Default packet architecture: Next.js + TypeScript web workspace, FastAPI/Python
on loopback 8000, private immutable local files and future SQLite run ledger,
TypeScript bridge to official Meterless reference. No hosted DB/Redis/auth/GPU.
Next workspace is `web`; provider secrets never enter browser bundles.
Vercel hosts only the Stage 1 web skeleton. Deploying a private evidence service
needs a future explicit hosting/trust design; never point a public page at a
private workstation or expose its port as a shortcut.

## Stage 2 — preservation verifier, only when requested

- `lastcopy/xml_compare.py`: expanded names, unordered attribute maps, ordered
  children/repeat occurrences; explicit formatting-only whitespace policy.
- `lastcopy/reconcile.py`: same-version/historical matching, six verdicts,
  slot-by-slot media byte checks; source coverage independent of completion.
- `lastcopy/ledger.py`: SQLite persisted run IDs, immutable evidence references,
  append-only events, bounded/cancellable jobs, registered input IDs.
- `lastcopy/cli.py`, `api.py`: same RunManifest execution boundary through CLI
  and POST /run; no arbitrary path or URL fetched from browser/model/archives.
- `fixtures/cases/*`, `tests/test_reconcile.py`, `test_limits.py`: independently
  authored expected results for stranded records, missing media, repeats, equal
  bytes under two filenames, limited CSV, retained history, conflicts, hostile
  inputs and missing coverage. At least three complete sample IO pairs plus a
  held-out variant. Demonstrate meaningful broken behavior fails then passes.
- Gate: offline network-denied real comparisons, evidence resolution, meaningful
  controls, CLI/API equivalence, cancellation and refresh-safe persisted state.

## Stage 3 — evidence-led connected investigation

- `lastcopy/providers/zetaris.py`: publish/query bounded evidence tables on
  existing approved prefix/deployment, retain query receipts and row provenance.
- `bridge/world-model.ts`, `lastcopy/world_model.py`: append evidence/hypotheses,
  preserve revisions, graph reads select unresolved work, stable idempotency.
- `lastcopy/providers/nightshift.py`, `actions.py`, `investigate.py`: actual
  discovered route, tool capability result, schema validation/code-owned
  dispatcher, 12-step/two-critique/300-second limits, honest serving identity.
- `tests/test_investigation.py`: provider outage never falls back; reviewer
  rejects missing-data hypothesis when raw repeats appear and changes action;
  another conflict stays unresolved. Graph evidence changes next action.
- Gate: real connected sponsor receipts and observable revision; Nemotron path
  blocked separately if concrete serving identity/meaningful work unavailable.

## Stage 4 — bounded recovery

- `lastcopy/recovery/plan.py`, `bundle.py`: target IDs, untouched XML/media,
  hashes, evidence, preconditions, supported operation and manual limitations.
- `apply.py`, `odk.py`, `attempts.py`: recheck before writes, serialize per
  submission, persist attempts, read back uncertain POST before retry, never
  manufacture instance IDs or overwrite a conflict; fresh verify afterward.
- `tests/test_recovery.py`: lost acknowledgement/restart, changed target version,
  conflict, missing bytes, already-complete plan; source hashes unchanged.
- Gate: actual dedicated Central synthetic recovery with before/request/after
  readback receipt and same verifier, repeated Apply creates no duplicate.

## Stage 5 — usable application

- `web/app/app`, `runs/[id]`, `components/import`, `evidence`, `recovery`: actual
  API-driven add→check→review→verify, evidence drawer, downloads, plan review,
  no unqualified safe-to-wipe assertion. Distinguish progress from preservation.
- Persist/reload/cancel/failed/empty/unknown states, keyboard/focus, mobile data
  layout; private credentials excluded from browser state, URLs and storage.
- Gate: full browser sample/import flow on real offline comparator; connected
  flow uses existing providers and recovery, not hardcoded result panels.

## Stage 6 — original code-built visual system and motion

- Inspect actual reference and existing UI, document observations without copying.
- Establish LastCopy tokens/typography/SVG document identity and narrative scene;
  premium finish across landing and product, not just a marketing shell.
- Coordinate motion with true state, static first frame, reduced motion,
  offscreen/hidden-tab pause. No generated imagery or fake activity.
- Gate: screenshots 360/390/768/1280/1440, 200% zoom, keyboard, reduced motion,
  no overflow, stable inputs and performant native scrolling.

## Stage 7 — acceptance and submission preparation

- Audit whole spec, all core/provider/recovery/browser paths and dependencies.
- Measure production mobile performance using a documented repeatable profile;
  report real Lighthouse/CLS/LCP numbers and limitations, never predicted scores.
- Prepare README, Docker guidance, sample IO, sanitized traces, architecture,
  limitations, 1–4 minute demo script and pitch outline. Recheck organizer rules.
- Gate: final readiness report with unresolved limitations and actual commands;
  no public visibility change, entry submission or organizer message automatically.
